# 大课程 → 小节 → 教学节点

网页的 CourseRoadmap 提供大课程规划，后端在 `curriculum.py`。沿用同一个模型适配器，`course_planner` 负责大课路线，原 `planner` 负责某一节内部的教学节点。二者职责和上下文分开。

```text
初二数学（课程名称约束学科）
└─ 本轮大课路线（目标、范围、自述基础、假设）
   ├─ 第1节 函数的含义（目标、预期结果、前置、时长）
   │  └─ 固定绑定一个 chat session
   │     └─ 本节节点 → 讲解、插问、测评、节点确认
   └─ 第2节 函数的表示 → 另一个 chat session
```

## 使用流程

在课程详情里填写大课目标，可补充教材范围和已有基础，选择单节时长与小节数量上限。模型调用 `plan_course`，按前置关系划分具体小节。未提供教材时必须说明按通用内容规划，不能编造教材对应关系。

页面生成按顺序排列的卡片，展示目标、可检查的学习结果、预期前置和时长。“按顺序开始”推荐第一节尚未确认完成的小节；也允许主动进入其他卡片复习或检查起点，不把预期前置当成已掌握，也不实施强制跳课锁。

进入卡片时才创建该节会话，首次自动把课程背景和本节任务交给安排 Agent，生成小课内节点并等待学生确认。无需重复初始化卡片。重复点击同一卡片、刷新或重启后，都恢复同一会话，不重复开课。

小节课堂的“保存并返回课程”只返回目录，不结束 session。每个节点仍沿用原确认与测评协议；当本节存在节点且全部节点已确认时，课程页显示本节已确认，推荐下一节。提早调用 `chat_end` 不会把未学完的小节算作已确认；此类已结束记录仍可回看，正常小节页面不提供提前结束操作。

## 数据与鉴权

新增两表，启动时幂等创建，不更改旧会话数据：

| 表 | 数据 |
| --- | --- |
| course_curricula | course_id、revision、status、job_id、plan JSON、inputs JSON、error、updated_at |
| curriculum_sections | 服务端生成的 id、所属课程、序号、内容 JSON、唯一 session_id |

旧会话和自由新建的小课仍在“补充小课与历史记录”。它们不自动冒充规划小节，也不因生成路线而被改写。绑定路线的小课不能单独移出课程，以免破坏小节入口和恢复关系。

目录、规划、打开小节和大课用量都使用原学习空间令牌；原 session 令牌和空间归属规则继续适用。卡片内容不含恢复令牌。大课规划用量按 `course_id` 归集，显示在路线下方；小节讲授/测评按原 session 计量，二者不会混成同一次调用。

## API 与后台任务

| 方法/路径 | 作用 |
| --- | --- |
| GET /api/courses/{cid} | 原响应增加 curriculum：规划状态、版本、有序 sections、确认数及推荐 next_section_id |
| POST /api/courses/{cid}/curriculum | 输入 expected_revision、goal、background、scope、lesson_minutes、section_limit；创建后台规划任务 |
| POST /api/courses/{cid}/sections/{section_id}/open | 原子创建或恢复固定会话；首次安排本节节点 |
| GET /api/courses/{cid}/usage | 仅当前课程的大课规划模型调用用量 |

参数边界：目标/范围/基础各至多500字；单节设定10–60分钟，小节数上限2–24。模型输出每节可估计5分钟至设定时长，数量1至指定上限，不强行凑数。

规划调用在数据库锁外执行，前端轮询状态；后台按 job_id、状态和课程签名校验过期结果，整份方案通过验证后才原子写入所有卡片。状态包括 empty、planning、ready、failed、interrupted。相同输入的重复提交复用进行中的任务，不重复调用模型；版本不符或不同输入撞上进行中的任务返回409。

尚未开过任何小节时允许调整目标后重新规划，旧路线只在新结果通过校验后替换。已有小节开始学习则保留路线，禁止重规划覆盖；可以添加补充小课。服务重启将 planning 标记为 interrupted，保留旧方案，不自动重试计费请求。

## 结构化校验与交接

`plan_course` 返回 goal、assumptions、sections。每节包含 title、objective、outcomes、prerequisite_indices、estimated_minutes。后端校验必填字段、类型、长度、数量、重复标题、时长及前置序号，只允许引用此前小节，杜绝自引用、前向引用和循环；服务端生成小节 UUID 并把序号解析成真实 id。

发布前继续经过课程范围检查。课程改名也检查尚未开课的小节标题，不能把数学路线改名成英语绕过约束。

读取会话时注入实时 `state.section`，公共状态与 `chat_classroom.context.section` 中包含本节目标/结果/前置及课程规划自述。首轮 job.intent 为 section_intake，只允许 ask/plan，不能直接开始授课。前置是规划预期，基础是学生自述；它们不会写成测评证据或长期掌握。

## 当前边界

结构验证与范围校验不等于教育专家已审核路线。内容主要由通用模型生成，尚无教材 RAG、课程标准映射或独立的前置知识语义核验；未提供范围时可能仅适合一轮阶段学习，不能声称覆盖整个学科。用户可在开课前补足目标/范围重新规划。

当前不自动合并跨小节认知画像，也不跨小节继承“掌握”标签。进程内 BackgroundTasks 不等于持久任务队列；多实例并发与完整课程增量编辑尚未实现。

## 验证

`tests/test_curriculum.py` 覆盖模型结果校验、真实 HTTP、版本/权限、开课幂等、节点确认进度、提前结束、失效结果、失败重试及重启恢复。

`tests/curriculum_browser.cjs` 使用 `tests/course_library_fixture.py` 的本地假模型与隔离数据库（8014端口），验证大课规划→小节卡片→本节节点→退出恢复→推荐下一节、桌面/手机及失败重试，不调用真实供应商。运行前执行 `npm run build`。
