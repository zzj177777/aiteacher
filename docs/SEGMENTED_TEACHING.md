# 分段讲授、理解检查与授课会话

2026-10-21

## 课堂行为

每个知识点任务拆为三个小段。每次只生成当前段的讲解，随后展示审核过的选择题或精确数值题。回答正确后学生点击继续，进入下一段；回答错误停留在当前段，提供针对性补讲，并换一道检查题。每段最多三道不同检查题，仍未通过则标为待复习，允许提问或暂存回原课堂，不静默跳过。

这些是有讲解、有反馈的随堂检查，只能作为理解观察，不计入独立测验的达标条件。

## 授课会话

任务内保存 protocol=2 及 session：当前段、总段数、段状态、已通过段、已完成要点、历次检查、当前检查ID、最近检查结果、讲解生成ID、使用过的例子标识、待解决/已解决疑问，以及原课堂的阶段、题目与步骤位置。

普通插问不切换教学段。回答完成不代表学生理解，学生可点击“这个疑问已解决”。暂存后当前段、检查题、错误记录与疑问仍保留，原课堂中提供恢复入口。全部段检查完成后才可正式交回调度器；学生仍可随时暂存或结束学习，系统如实记录未完成部分。

## 技术实现

- backend/teaching_content.py：9个审核教学单元，每个含3道检查；四种主题各组合三个单元。
- backend/teaching_session.py：会话状态、精确判分、分支、暂停/恢复、疑问跟踪、旧任务升级和公开数据投影。
- backend/lecturer.py：授课模型只收到当前段材料、最近检查与会话摘要；不收到尚未作答检查的答案。
- backend/app.py：后台结果绑定任务与段生成ID。普通聊天增加课堂revision不再使当前讲稿失效；切段、暂停和取消会使旧生成失效。答疑也按语义课堂位置检查过期。
- src/main.tsx / src/teaching.css：段进度、理解检查、补讲提示、疑问列表、会话记录、暂停/恢复；报告与Markdown笔记包含讲授轨迹。

服务重启保留当前段的本地讲稿和检查，未完成问答标为待追问。旧版正在进行的整段讲授会保留历史并升级至分段会话，不追溯认定已通过检查。

## 验证与边界

44项自动测试覆盖分支、无跳过、题目换新、重复错误、题目答案不泄露、插问记忆、暂停恢复、真实HTTP持久化、旧任务升级、模型失败、过期结果、服务恢复及完整课堂回归。

首版检查采用审核题库与确定规则，不将任意自然语言解释自动判为通过。补讲由模型依据审核材料与错误观察生成，仍需真实学生试用评估教学效果。连续三题未通过后不会自动生成无限新题，保留待复习状态。
