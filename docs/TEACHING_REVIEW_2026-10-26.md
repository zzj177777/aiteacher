# AI 私教：问题复盘与候选解决方案

日期：2026-10-26  
状态：讨论纪要与设计备忘，非已批准实施方案。  
范围：本轮产品评审、学生学习模型、课程知识结构、一对一教学经验，以及授课 Agent 优化讨论。今晚只整理文档，不修改应用代码、数据库、配置或运行中的服务。

## 1. 本轮讨论的核心目标

最初希望解决真人私教价格高、质量不稳定的问题。经过原型开发，关注点逐渐从“AI能不能讲知识”转向“AI能否了解具体学生、找到真实卡点、采取有效帮助，并让学生能够独立完成任务”。

当前最突出的用户反馈：授课 Agent 面对不同知识点经常照本宣科，内容古板、冗长，像输出讲义，缺乏一对一老师根据学生反应调整的过程。该反馈明确了优化方向，但频率和严重程度还需要用实际课堂案例测量。

产品效果应由学习表现、持续使用和真实用户反馈验证，不能由 Agent 数量、绘图工具数量或程序测试通过数量替代。

## 3. 从人类教师经验得到的启发

用户的实际经历：自己相对擅长学习、做题和考试，大学期间辅导过初高中学生。优势包括记得自己从不会到会的过程，知道学生容易困惑的地方，对知识重要性与应试方法有判断；重视发现前置知识缺漏和基础能力不足，回补后用简单直接的方法教新内容，帮助学生克服陌生感并建立信心。

这些经验可以转化为以下设计原则：

1. 保留“初学者为什么难”的视角，记录典型误解、解释入口和有效例子，而不仅是标准知识。
2. 区分当前概念不理解、前置缺漏、基础操作不熟、方法选择困难以及不敢开始等情况；不根据一次错误武断归因。
3. 回补服务于当前目标，保存暂停原因与返回位置，补完回到原题或原任务。
4. 按学习目标、考试要求、时间与修复价值确定优先级，不平均用力；考试重点需有具体材料依据。
5. 逐步撤去帮助，关注学生独立完成了什么；用具体进步支持信心，不依靠空泛鼓励或长期降低难度。
6. 用户个人有效的方法是教学候选经验，不能假定适合所有学生；需要根据学生反馈调整。

建议收集真实案例：学生原话/错误步骤 → 教师判断 → 采取的行动及理由 → 学生反应 → 如何调整 → 最终独立表现。案例用于设计与评测时，应去掉不必要的个人身份信息。

## 4. 问题清单与可能方案

### P01：授课目标过于宽泛，容易生成整篇讲义

现象：收到“讲某知识点”的任务后，模型倾向于覆盖定义、性质、推导、例题等全部内容。提示中已有“小要点”要求，但尚不足以保证实际输出节奏。

可能原因：任务缺少学生当前卡点与结束条件；输出协议仍以一段message为主；系统没有稳定评价“这段讲解是否帮助学生跨过障碍”。这些是设计分析，不是已通过实验确认的唯一原因。

候选方案：任务卡增加本轮小目标、学生原话/错误步骤、已确认基础、待确认问题和结束条件。信息不足时先做一个短澄清，不默认生成完整讲稿。

验收示例：学生只问一个符号，不从整章定义重新开始；能够围绕当前障碍给出一个可完成的小步骤。

### P02：授课动作单一，学生反应不能充分改变过程

候选方案：允许授课 Agent 返回一次教学动作，例如澄清、预测、对比例子、示范一步、提示、解释自己的做法、图形操作。程序管理“等待回应”的状态，包括刚才做了什么、期待何种回应、提供过多少帮助、原任务返回位置。

交互节奏：一个动作 → 学生回应 → 观察与判断 → 下一动作。学生可要求直接讲解、举例或跳过，避免把互动变成连续审问。

约束：随堂理解检查与正式测评区分；不把每次点击、看图或复述记作掌握。内容长度只是辅助约束，不能以字数代替教学质量。

验收示例：同一开场之后，学生回答正确、表达困惑、提出新问题时，系统选择不同后续动作；插问结束后能回到原任务。

### P03：学生长期记忆薄弱，存在跨课堂从头认识的问题

现状：模型主要使用最近24条对话、12条证据和8条当前计划交接；完整历史保存不等于会被持续利用。尚无稳定的跨课堂学生学习模型。

候选方案：建立稳定的匿名学生ID，将课堂关联到同一学生；分开存储学习经历、能力判断、偏好与当前课堂状态。生成按任务选择的记忆视图，必要时检索原始证据。

约束：学生可查看与纠正目标、偏好及不准确记录；不默认合并身份不明的旧会话。数据更正、删除和跨会话关联规则需要设计。

验收示例：昨天在提示下完成，今天新开课堂时记得需要独立验证；验证通过后更新判断，而不是一直把学生当成不会。

### P04：希望“全面准确的画像”，但固定标签可能制造虚假确定性

讨论结论：可以设计可扩展的数据结构，但无法靠字段齐全保证判断准确。一次答错可能来自不同原因，精确百分比需要有定义和验证。

候选方案：证据与结论分离。记录能做什么、独立程度、评判来源、时间、支持/反对证据及尚未知的内容。状态先使用未检查、需帮助、已有独立证据、需复查等可解释描述；理解、操作、解释和迁移分别记录，不强行合成单一等级。

对假设保留候选原因，例如“可能漏记换行符号”，允许验证、撤销和修正。偏好区分学生自述与教学效果观察，不把“喜欢图解”固化成所谓固定学习类型。

验收示例：一次错误不会生成永久的“粗心/基础差”标签；改正评分或原题答案后，相关能力判断可以重新计算。

### P05：缺少课程知识地图，模型不知道本学期需要掌握什么

用户提出的重点：明确教材与学期单元、前置知识、单元联系、知识点及其依赖，才能定位孩子的学习情况并指导更多行动。

候选结构：课程/教材版本 → 学期 → 单元 → 可检查能力节点；另建包含、必要前置、支撑、应用及教学顺序等不同关系。学习状态附着于稳定节点ID，题目和证据关联相应节点。

例子（非特定教材目录）：十个一换一个十 → 解释满十进位 → 在竖式中处理进位 → 独立完成进位加法。先覆盖正在学的单元，不预先生成整个学科的全部微小节点。

约束：依赖用于指引检查，不代表后续出错就能推断前置全不会。节点名称不能随每轮生成而漂移；跨教材映射、版本升级和同义节点合并需审核。第一版可以使用关系数据库，无需立即采用图数据库。

待决定：优先跟随学校教材，还是自由探索；三年级数学是讨论示例，尚未决定项目转为小学产品，也尚未选教材版本。

### P06：可能的错因很多，直接补一整节课效率低

探索方案：建立“目标—证据—候选假设—教学干预—验证”记录。例如区分不理解规则、知道规则但操作遗漏、算术错误，再选择一个短任务验证。

选择教学行动时考虑：是否有助于目标、能否区分关键疑问、学生负担和预期收益。先做简单可解释规则，不承诺精确的自动最优决策。

与知识地图的关系：地图提供可检查的前置与能力范围，假设机制决定眼下应该检查哪里；二者可结合，不必二选一。

风险：过度诊断、问题过多、把偶发错误解释过度。设置诊断长度与停止条件，证据足够就开始教，并允许学生直接进入讲解。

### P07：缺少关于“怎么教”的经验材料

候选方案：建设小型教学案例库，覆盖典型卡点、成功与失败讲法、适用基础、下一步检查及调整原因。针对当前任务检索少量相关案例，而不是把全部案例塞入上下文。

区分三类材料：课程地图说明教什么；学生记录说明当前情况；教学案例说明有哪些可尝试的方法。记忆个性化不等于模型自动获得更高教学水平。

验收示例：同一知识点面对两种不同误解，采用不同解释入口，并根据后续表现调整。

### P08：出题与评分缺少独立核验

现状：通用出题、参考标准和评判来自模型体系，可能共同犯错；已有旧版行列式精确验证并不等于通用数学核验。

候选方案：可计算问题调用确定性数学工具；开放题使用明确维度、接受等价答案，信息不足时追问或待确认。建立人工审核的题目与学生回答案例集，测量错误判分、泄露答案、歧义题等问题。

约束：额外增加同模型审核Agent不能保证独立正确；提示后改正不能替代新题独立验证。

### P09：缺少教学质量和学习效果评测

候选方案：分别评估工程可靠性、教学行为质量和真实学习效果。教学片段检查针对性、重复、认知跨度、是否过早给答案、是否有合适的学生行动、内容正确性。以实际学生前测、不同题后测及延迟复查观察变化。

评测案例建议至少覆盖：两种错因导致同一错误、接受提示后答对、合理等价解、学生说懂但不会应用、插问后返回、图形操作预测、误判后更正、跨课堂复查。

约束：小规模试用首先用于发现问题，不据少量样本宣称教学效果优越；模型评分只作辅助，测试通过数量不代表教得好。

### P10：帮助学生建立信心尚未成为明确课堂设计

候选方案：降低起步跨度，让学生完成真实的小步骤；记录独立完成部分与提示程度，逐步撤去帮助；反馈具体到可观察的进步。学生自述与行为观察分开，不根据沉默或单次错误推断心理状态。

验收示例：从需要示范到只需起步提示再到独立完成，系统能给出对应反馈；不靠不断给简单题制造虚假成功。

### P11：产品范围宽，差异化和付费价值尚未验证

候选方案：底层保持通用，首轮真实试用聚焦明确人群与场景。价值主张围绕更快找到卡点、有效回补、独立完成和下次接着学，而非展示多Agent技术。

需观察：完成率、再次使用、独立新题表现、学生/家长愿付费的具体价值、有效辅导会话成本。小学用户、大学生应试和自由学习尚未作最终商业取舍。

### P12：报告、运行观测和持续维护仍有缺口

报告目前主要汇集记录；候选方案是基于证据整理“今天学了什么、能独立做什么、哪里还不确定、下次从哪继续”。

已补用量/成本及错误诊断，后续仍可增加提示词/策略版本、业务校验结果与调用的关联、预算和耗时目标。进程内任务、串行等待、不能主动取消旧网络请求仍是限制；是否上可靠任务队列依据实际试用负载决定。

文档冲突已做范围整理，后续功能变更要同步当前说明与协议，避免重新混入旧模式能力。绘图与公式兼容已改善，不代表任意模型输出都保证正确；图形操作目前不自动形成教学证据。

## 5. 候选整体结构：供后续评审，不是最终选型

```text
课程知识地图 + 学生目标/时间条件
                    ↓
相关学习证据 + 能力状态 + 未解决假设
                    ↓
安排Agent选择一个小目标和教学行动
                    ↓
授课/测评/绘图工具实施 → 学生回应
                    ↓
程序校验并追加证据 → 更新判断 → 决定下一步
```

建议长期数据对象：学生、课程/版本、能力节点与关系、课堂、练习证据、能力状态、困难假设、教学干预、偏好、当前返回位置。并非要求下一次一次性实现全部表。

角色权限建议：授课报告讲过与帮助，测评报告观察，安排选择动作；受控记忆模块负责校验并保存更新。模型不直接任意重写整份学生档案。每次只提供与任务相关的记忆视图。

## 6. 推荐的后续实施顺序（尚未批准）

| 顺序 | 工作 | 最小验收结果 |
| --- | --- | --- |
| 1 | 整理真实授课问题片段和优秀教学案例，建立少量基准 | 能明确指出哪里冗长、哪里误判、什么样的回应更合适 |
| 2 | 小目标任务卡 + 单次教学动作 + 等待回应/返回状态 | 学生不同回应改变下一步；不自动生成整节讲义 |
| 3 | 选定教材或明确课程范围，完成一个单元的能力地图 | 能把作答定位到能力并检查相关前置 |
| 4 | 稳定学生ID、跨课堂证据与能力状态 | 新课能承接上次未完成验证，判断可追溯和更正 |
| 5 | 逐步加入错因假设、干预反馈、复查安排 | 能区分同错不同因，验证修复是否有效 |
| 6 | 小规模真实学生试用，再决定扩展 | 用效果、体验与成本决定后续投入 |

每一步都应保留兼容和迁移方案；先验证教学行为改进，再扩大Agent数量或工具范围。

## 7. 下一次讨论需要决定的问题

1. 首批验证对象是谁？小学三年级只是示例，还是实际要优先服务的群体？
2. 若按学校进度教学，使用哪个教材版本、学期和具体单元？
3. 优先改善哪种课堂片段：概念解释、算术/操作、应用题、考试解题策略？
4. 用户能否提供若干真实教学案例，尤其是第一次讲法失败后怎样调整的案例？
5. 对“简短、互动、有效”的验收标准是什么？学生要求完整讲解时怎样调整？
6. 哪些信息由学生/家长确认，哪些由系统推断？如何查看、纠正和删除长期记录？
7. 如何平衡自主探索、学校进度、考试效率和理解深度？

## 8. 下次开始前的提醒

本轮形成的是候选设计，没有决定立刻建立大型知识图谱、复杂认知概率模型、新Agent集群或训练模型。不要将本文中的示意能力链当作审核过的教材标准，也不要将教学假设当作已确认事实。

当前优先问题是授课行为：理解学生眼下的卡点，用合适的小步骤帮助他行动，获得反馈后再继续。长期画像、课程地图和教学案例应服务于这一过程。
