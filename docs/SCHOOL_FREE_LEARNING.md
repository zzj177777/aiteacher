# 学科自由小课

## 用户流程

进入任一科目页，既可浏览年级学期，也可点击「自由开始学习」。此时只带入用户选择的学段与科目，不要求填写学习卡片，不携带年级、学期、教材或预设掌握程度。

新小课先显示简短的本地欢迎语，不自动调用模型。用户直接输入知识点时进入简短小课规划；输入「我不知道学什么」或点击「还没想好，给我几个选项」时，教学安排 Agent 提供可点击的小课方向。选择后先给简短计划，点击「按这个计划开始」或通过聊天确认，再调度授课 Agent。用户可输入自己的内容，不必接受推荐。

同一科目页列出尚未归入长期课程的历史自由小课，可继续原会话；返回科目、刷新、新建学习会话都保留或重新带入正确的科目背景。已归入长期课程的小课仍从原课程管理入口恢复。上/下学期目录本身仍是占位框架，不因自由小课上线而宣称已有章节内容。

## 数据与 API

`POST /api/sessions` 的聊天模式可带：

```json
{"mode":"chat","school_context":{"stage_id":"junior","subject_id":"math"}}
```

后端 `school_learning.SchoolSelection` 验证 21 个有效学段科目组合，只允许 `stage_id` 和 `subject_id`，中文标签由服务器补充。不能同时绑定 `course_id`，不支持经典/旧规划模式。上下文保存于会话 JSON 的 `school_context`，无新数据库表或迁移；学生后来的基础自述不会覆盖入口上下文。

公开快照和课堂 Agent 的上下文包含 `school_context`。课程目录查询的小课摘要也包含该信息，供前端按科目恢复。主教学规划、讲授、测评，以及通俗解释和划词解释都会接收背景。入口选择只证明用户选择了学段科目，不证明其已掌握任何知识。

聊天事件沿用原来的鉴权、revision 和 idempotency_key：

- `chat_message`：首次明确需求触发 `school_intake`；明确“不知道学什么”触发 `school_topics`。不把“不知道怎么解方程”这种具体困难误判为无目标。
- `chat_suggest_topics`：请求几个可选方向，仅用于尚未选定目标的学科小课。
- `chat_choose_topic`：payload 为 `{"choice_id":"服务器返回的选项ID"}`。只能选择当前有效选项；不存在、过期或已选后的选项返回 422。选择后记为学生消息并进入短课规划。
- 学科自由小课不接受 `chat_intake` 初始化卡片；已有通用聊天与长期课程仍保留其原有卡片流程。

会话 `topic_choices` 保存当前有效选项；对应教师消息保留 `topic_choices` 以供回看。发送新消息、重新推荐或选择方向会清除当前有效选项，旧消息上的卡片随即禁用；历史文本不删。刷新与服务重启恢复原选项，不会自动重新调用模型。

## 调度与约束

`school_topics` 使用现有教学安排 Agent，通过 `suggest_learning_topics` 工具返回 `message` 与 `choices`。建议 3 个方向，程序要求 2–4 个互不重复的选项，字段长度、结构和学科范围均校验。推荐阶段不能创建计划、直接讲课或出题；失败保持可重试，不填充伪造结果。

`school_intake` 沿用 `arrange_learning`，程序仅接受 ask/plan。短课最多 4 个节点，避免直接生成整学期大纲；不自动讲课，等待学生确认。后续继续使用已有讲授、插问、举例、测评、学习报告和费用记录流程。

学科上下文通过 `school_learning.scope` 接入既有课程范围检查：检查学生请求、候选方向、计划和专家输出，必要前置回补允许，无关换科请求拒绝且保留进度。将自由小课归入长期课程时，也先检查固定学科是否匹配。不能仅靠改消息文本或修改基础自述绕过已选科目。范围检查仍包含模型判断，年级适配和教学内容质量不是严格正确性保证。

推荐调用按 planner 记录费用。调试面板保存其真实模型请求和回复，工具名为 `suggest_learning_topics`；所有调试与学习记录仍需会话凭据。推荐不是内部推理过程，不输出隐藏思维链。

## 前端与交接

- `SchoolCatalog.tsx`：自由入口、进入错误、历史小课列表；年级学期入口保留。
- `CourseLibrary.tsx`：显式点击创建会话并归属当前学习空间；防重复点击。导航 `classroom` 可附 `return_view=school`、`stage_id`、`subject_id`，返回原科目。刷新时服务端会话上下文优先，浏览器入口参数不能改变已有课堂的科目。
- `ChatApp.tsx`：有学校上下文时跳过卡片；显示学段科目、选项按钮、明确的计划确认入口；普通课堂流程不变。
- `backend/chat_classroom.py`：推荐、选项失效、短课初始调度与上下文交接。
- `backend/school_learning.py`：有效组合、服务器标签与范围背景，不依赖教材或知识图谱。

新增学段或科目时同步前后端有效组合；不要直接放开任意中文标签作为系统上下文。需要真正按年级、教材或知识掌握情况适配时，再增加带来源的字段，不从入口名称猜测。

验证：`test_school_learning.py` 检查建议结构、调度边界、过期选项与上下文；`test_school_api.py` 用隔离数据库和本地模型替身验证 21 个入口、请求幂等、鉴权、跨科拦截和重启恢复；`school_free_chat_browser.cjs` 在本地替身服务验证两条学习路径、确认讲授、刷新、历史小课、新会话、手机显示。测试不使用真实 DeepSeek 额度。
